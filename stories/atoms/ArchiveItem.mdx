# ArchiveItem (Figma: `atom/ArchiveItem`, `1421:18214`)

## Uso

Linha/card compacto pra representar **um arquivo arquivado** dentro de uma lista — ícone de tipo, nome e controle de seleção. Use dentro de listas de arquivos onde cada item precisa ser selecionável (`idle`/`hover`/`pressed`/`selected`/`disabled`). Mesma anatomia de `FolderItem`/`ImageItem`/`VideoItem`, um por tipo de conteúdo — escolha pelo tipo real do arquivo, não misture.

## Eixo `tier` mencionado na descrição — gap, não implementado (Regra 9)

A descrição do componente menciona "badge de tier", mas `get_design_context`
no nó real só retorna o eixo `state` (9 valores no component set) — nenhum
eixo `tier` existe como prop, e nenhum badge de tier aparece no screenshot
renderizado do componente. Interpretação mais provável: a frase se refere a
compor este átomo com `atom/StorageTierBadge` (`1457:21014`, Regra 6)
externamente numa tela (ex.: linha de arquivo grande em
`organism/cleanSpaceStorage`), não um eixo interno. Documentado como gap
aberto em vez de inventar uma prop `tier` sem base no Figma real.

## Consolidação dos 9 valores de `state` do Figma em 7

O component set real expõe `Idle`, `hover`, `pressed`, `disable`,
`Selected - Pressed`, `Default`, `Static`, `Selected`, `Selected - Hover`.
`Default` e `Static` (esta última só válida com `property2="ArchiveItem"`)
usam o mesmo asset base de `Idle` (`Rectangle13`) e são visualmente
idênticas a ela no screenshot — variações internas de autoria do Figma
(prováveis artefatos de como o component set foi montado), não estados de
produto distintos. Consolidadas em `idle` para não expor 2 props redundantes
sem diferença visual observável.

Sem nota de `reduced-motion` visível no Figma — não documentado. Transição
de estado é instantânea (troca de asset), controlada externamente via prop
`state` pelo componente pai (ex.: uma grade de arquivos gerenciando seleção).
