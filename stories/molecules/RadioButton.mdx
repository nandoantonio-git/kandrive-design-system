# RadioButton (`molecule/radioButton`)

## Uso

Botão de rádio pra selecionar **1 opção entre um grupo mutuamente exclusivo**. Pra seleção múltipla/independente, use `Switch` ou o indicador de seleção de item (`SelectState`), não este componente.

## Bug de extração corrigido (Regra 9)

O `get_design_context` retornou código de referência com o `<p>` do label
**hardcoded como "Pessoal" nas 2 variantes** — mesmo a segunda variante
tendo node id/nome (`Property 1=Radio: Guardados`, confirmado via
`get_metadata`) claramente apontando para "Guardados". Corrigido para usar
o rótulo correto por opção (`personal` → "Pessoal", `saved` → "Guardados"),
com o nome do symbol Figma como fonte de verdade, não o texto renderizado
defeituoso.

## API

`option: "personal" | "saved"` + `checked`/`onCheckedChange` (controlado,
igual padrão de `atom/switch`) em vez de replicar `Property 1` como string
literal do Figma (`"Radio: Pessoal"`) — nomes semânticos mais limpos para a
API de código, mesmo conceito.

## Terminologia (Regra 5)

"Pessoal" e "Guardados" não constam na lista aprovada/proibida da Regra 5 —
não é terminologia do domínio de armazenamento regulado por ela (contexto
aqui é filtro de arquivos "meus"/"guardados" num seletor genérico, 🧩
inferido pelo nome, sem tela do inventário confirmando o uso exato).

## Estados (Regra 8)

| Estado | Aplicável? | Nota |
| --- | --- | --- |
| Unchecked | ✅ | Círculo vazio, borda `zinc-400` |

| Loading/Error | ❌ Não aplicável | Controle de seleção simples |

## Fluid interface (Regra 8)

`transition-colors` na borda (interruptível), `active:scale-90` dá feedback
imediato no press, antes do release. **reduced-motion: não documentado no
Figma** — nenhuma variante/nota encontrada no nó consultado; `motion-safe:`
aplicado por padrão de engenharia.
